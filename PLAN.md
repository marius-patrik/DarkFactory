# DarkFactory-Paper — Completion Plan

This plan is the execution order from the current repository state to the final thesis. Durable writing/structure rules live in `AGENTS.md`.

## Thesis argument

Section 1 owns the argument:

**jak AI mění vývoj softwaru → co model skutečně je a dokáže → co kolem něj přidává Harness → jak se tyto mechanismy záměrně skládají do agentního chování → jak je realizuje DarkFactory → co o výsledku ukazují důkazy**

The rest of the thesis demonstrates this chain instead of repeating it.

## Execution order

### Phase 1 — Lock structure and vocabulary

Goal: finish the architecture of the thesis before rewriting content.

- verify the full rendered hierarchy against the causal argument;
- finalize every section title;
- finalize every surviving semantic article;
- finalize every `term` / `keyword` value;
- ensure each keyword has exactly one semantic owner;
- confirm section-owned terms such as Harness and Agentické inženýrství;
- remove any remaining article that does not own unique meaning;
- verify no deleted taxonomy survives in manifests, relations, docs, validators, or generated indexes.

Exit:
- hierarchy is frozen;
- vocabulary is frozen;
- semantic relation graph resolves;
- no compatibility/legacy terminology API remains.

### Phase 2 — Rewrite Theory completely

Goal: rewrite 2.2–2.5 as one causal argument, not preserve old article prose.

Order:
1. 2.2 AI-asistovaný vývoj
2. 2.3 Jazykový model a inference
3. 2.4 Harness
4. 2.5 Agentické inženýrství

For every level-2 section:
- write Úvod only as scope/transition;
- rewrite every surviving article from its single semantic responsibility;
- fold deleted concepts into their true owners only where needed;
- write Závěr only as synthesis/bridge;
- eliminate semantic duplication across sibling articles and across sections;
- replace hand-written terminology mentions with canonical `term(...)` references where appropriate.

Specific boundary:
- Model ends at inference and its limits.
- Harness begins with persistent state, repeated execution, environment, tools, and extensibility.
- Agentické inženýrství begins where those Harness capabilities are deliberately composed, constrained, and orchestrated.

Exit:
- Theory reads continuously from AI-assisted development → Model → Harness → Agentické inženýrství;
- every statement has one owner;
- no article exists only for glossary completeness.

### Phase 3 — Theory citation/source pass

Goal: make the rewritten Theory academically defensible after its prose is stable.

- primary/originating paper or standard where possible;
- first-party documentation for contemporary agent/tool/runtime mechanisms;
- claim-local citations;
- remove citations that merely decorate paragraphs;
- verify thesis-defined terms are explicitly marked as such;
- delete bibliography entries no longer used after the rewrite.

Exit:
- every external definition/mechanism/history/security claim has an appropriate source;
- bibliography contains only used sources.

### Phase 8 — Thesis-wide single-owner deduplication

Goal: remove semantic repetition after all sections exist in final form.

Audit in order:
1. Theory internally;
2. Section 1 ↔ Theory;
3. Theory ↔ generated 3.2;
4. Theory/generated docs ↔ 3.3;
5. Practical ↔ Results;
6. Results ↔ Conclusion.

For every repeated statement:
- choose one canonical owner;
- replace other explanations with a necessary semantic reference or delete them.

Do not use word-frequency rules. Repetition is allowed only when grammatically necessary or when the relationship itself is new information.

Exit:
- no known duplicated definition, mechanism, example, limitation, or evidence claim remains.
